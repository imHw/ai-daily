今日主线

OpenAI 推进产品简化战略，Vercel 公开 DHH vs Rust 之争，Box CEO 描述 AI 时代就业结构重构

Vercel CEO Guillermo Rauch 正式发布 gdp-ts（Ghosts of Departed Proofs for TypeScript）——一个面向 TypeScript 的库、linter 和 AI skill，核心理念是「敏感的 API 操作必须附带授权证明」。通过类型系统，在编译阶段验证调用方是否已完成鉴权检查，从而阻止团队和 Agent 在运行时才暴露安全问题。Rauch 指出，Agent 正在以远超人工 code review 的速度生成代码，而 Rust 的 borrow checker 范式正是为这种场景设计的——tight constraints，让 agent thrive in tight loops。

Box CEO Aaron Levie 从另一角度切入企业 Agent 落地：真正的瓶颈不是模型能力，而是「测试、调优和优化 Agent 在真实工作环境中的表现」。企业缺乏统一的 eval 基础设施来模拟 CRM、邮箱、文件系统等真实场景，每家公司都要自己搭建，效率极低。他认为这将是未来企业 IT 的一个重要细分市场。

Meta 首席 AI 总监 Madhu Guru 提出了一个更根本的观点：「团队最常犯的错误是把 eval 当作 Agent 构建完成后再加的 QA 步骤。AI 产品本质上不同——你的 eval 就是产品规格。」这一观点与 Rauch 的 gdp-ts 思路高度一致：把质量保障前移，在构建阶段就内嵌而非事后补救。

Guillermo Rauch @rauchg · CEO @Vercel

发布 gdp-ts：Ghost of Departed Proofs for TypeScript。核心思路是让敏感 API 操作在编译时要求「证明」——比如修改密码必须附带角色和权限验证的证明，类型检查器会在编译期直接拦截错误。他强调，Agent 正在以远超人工 code review 的速度生成代码，而 Rust 的 borrow checker 范式正是为这种场景设计的——tight constraints，让 agent thrive in tight loops。 原推 →

Aaron Levie @levie · CEO @Box

企业 Agent 部署的最大瓶颈在于 eval 基础设施：Agent 需要访问真实文件、CRM、邮件等环境才能被有效测试和调优，但现在每家公司都得从零自建，速度慢且无法复用。未来每家企业都需要专人管理 eval 体系、构建模拟环境的 infra。这是一个巨大的市场空间。 原推 →
